## Why Filler SDK?

The UniswapX solver layer is monopolized by ~10 institutional desks (Wintermute, SCP, Propeller, Barter) optimized for majors. Why? Because day-1 of building a solver costs ~4 weeks of infra:

- A custom v4 hook-event indexer
- Inventory tracking + per-pool simulation
- Atomic JIT add → swap → remove orchestration
- MEV protection + retry logic + monitoring

Filler SDK is the **infrastructure** for that day-1, packaged. We don't compete with Wintermute on majors. We enable the 50+ verticals where they don't reach:

- **Hook-specific solvers** — every new v4 hook is a 6–12 month window without coverage
- **Treasury internalization** — DAOs filling their own rebalances instead of paying spread to aggregators
- **LVR-aware strategies** — redistributing LVR back to LPs as core mechanic
- **Atomic compound fills** — yield deposits, hedge legs, governance actions in one tx

## Three files and a bond

Every solver shipped with Filler SDK looks the same:

```
my-solver/
├── src/
│   ├── filler.ts      # subscribes to intents, calls the SDK
│   ├── strategy.ts    # filter + decide(intent) → bool
│   └── config.ts      # env-validated config
└── package.json
```

Plus one on-chain bond — `FillerBond.stake(0.1 ETH)` — and the solver is operational. [See the quickstart →](/docs/quickstart)
